# Changes

What changed in each version of phenom-translator (phnt), newest first. Versions follow the date: YYYY.MM.DD.N, N
counting the releases of that day. The version is set in one place, `phenom_translator/__init__.py`;
`phnt --version` prints it.

| Version | Changes |
|---|---|
| 2026.11.23.6 | From the second watch on the XL (with .5, 2026-11-23 16:50): two images, an EDS spot spectrum and a sample exchange in the Phenom UI, all seen. **Refusals that are states, not faults** (`adapter.UNAVAILABLE`, reported under `unavailable`, not `read_errors`): the Phenom UI's EDS holds the detector (`Access denied trying to open Spectrometer device`), and the HFW range cannot be read outside NavCam/SEM (unloading, loading, selecting the SEM). The summary has `eds`: idle, acquiring or busy elsewhere; busy elsewhere is a warning and makes `eds_ready` false. **The watch**: a change compares only the reads made every time, so a read only in the full status no longer makes two 'changes' every 30 s; the 30 s line says 'no change in the last 30 s' only when that is true; pressures to 3 significant figures (a venting chamber read 0.004 Pa, shown as 0). A fourth largest-field point: 1003.2 µm at WD 8.7 mm. 76 tests. |
| 2026.11.23.5 | From the first watch on the XL (with .3, 2026-11-23): 90 full reads in 180 s, 0.39 s each, no read errors, one pump-down (18.8 → 0.1 Pa in ~36 s), and every pressure step logged as a change because the pressure was in the warning text. **The watch reads quickly**: `Adapter.quick()` reads only what changes from second to second (modes, door, SED, charge reduction, viewing mode, spectrometer), every 0.5 s by default, with a full status every 30 s; a change is a change of state (modes, door, scan, EDS acquiring, vacuum stable, SED, `can_image`, which reads fail), shown with the pressure; the JSON keeps the pressure trace (`watch.trace`) and the read times of quick and full reads apart. **The largest field by WD is interpolated** (linear between the fields seen, extrapolated beyond them; `profile.hfw_max_um`) instead of taken from the nearest shorter WD; the third point (726.0 µm at WD 3.3 mm) is in the defaults. The report's NOW line has the pressure rounded and the largest field at this WD. 74 tests. |
| 2026.11.23.4 | `phnt report` at the instrument looked stuck: nothing was printed during the watch, and its one notice went to stderr, which PowerShell ISE shows as a red NativeCommandError. Now everything goes to stdout: a first line saying what it does, each change as it happens, a line every 30 s while nothing changes, then the text. |
| 2026.11.23.3 | **`phnt report`**: everything for a test session at the instrument in one command and two files (a short text to paste, `--out FILE`, default `PHNT_OUT/report_<time>.txt`; the full JSON next to it): versions and how PyPhenom was found, the instrument now with every property and the time a status read takes, the profile in use and the proposal (limits, differences), PyPhenom's simulator (with `PHNT_MODE=phenom`); `--watch S --every S` reads the status for S seconds while someone uses the Phenom UI and lists every change (modes, scan, door, EDS acquiring, vacuum, SED, warnings) with its time, read errors by read and mode, and the read time (mean, max). Read only. The fake XL reads its state afresh on every call, as the XL would. 72 tests. |
| 2026.11.23.2 | From the first run on the XL (TESTING T0, T2, T4; 2026-11-23 16:08). **The largest field depends on the WD** (877 µm at WD 6.3 mm, 755 µm at 3.9 mm): a discovery no longer narrows `ranges.hfw_um` (the widest seen is kept) and records `ranges.hfw_max_um_at_wd_mm`; validation warns (does not refuse) a field larger than what the nearest shorter WD allowed. **Vacuum and SED in the status**: a charge-reduction state that is not stable (the XL read target Off, 12.9 Pa, settling) and an SED that is `NotAllowed` are warnings now, and the summary has `vacuum_stable`, `pressure_pa` and `sed`. The holder's name as PyPhenom gives it (`XL Manual Height`) in the fake and the defaults, so a discovery no longer reports a false change. 68 tests. |
| 2026.11.23.1 | **Phase 1.** The adapter (the only module that imports PyPhenom) with tier-0, read-only verbs: modes, door, holder, stage and stroke, HFW, kV (positive; PyPhenom reports it negative), spot, emission, WD, SED, charge reduction, exclusive access, viewing mode, beam blanking, EDS detector temperature, health, PPI licenses, activated features, properties; a status with a summary (`can_image`, `eds_ready`) and warnings; tables of the PyPhenom names allowed (by tier) and forbidden, checked against the source by a test. The fake XL (`PHNT_MODE=fake`) answers as the XL did on 2026-11-23; PyPhenom's simulator as `PHNT_MODE=ppisim`. The machine profile: defaults and timings from the discovery, a proposal from `phnt instrument discover`, import (reviewed) and set by a person only. The study format: per-kind schemas that both validate and generate `study_format` (image, navcam, move, focus, montage, series, calibration, particles, eds_point, eds_grid), each error with its fix; checks of kV and spot against the caps (sensitive samples lower), stage offsets, scan centre and EDS spots in fractions of the field width, EDS live time (a spectrum cannot be stopped early), the EDX working-distance windows, grid and montage sizes, the request's total time. Estimates from the measured timings (images, EDS spectra, spot moves) and assumed ones (stage, autofocus) marked as such. CLI `phnt` and MCP server `phnt-mcp` (study_format, validate_studies, instrument). The discovery (PyPhenom dumps, probe, license checks, three EDS bring-up rounds) in `docs/discovery`. Checked against llm-translators' `create_new_translators.md` (where it applies to a local instrument translator; the decisions are in planning.md). `validate` returns `{name: {ok, kind, errors, warnings, estimate, runs_from_phase}}` (an empty request: `{"_": ...}`); study names are checked (they name folders); each study is capped at `limits.study_minutes_max` (60 min) or `PHNT_MAX_MINUTES`, the request as a whole only warned above `limits.request_minutes_max`. `tool_status()` leads with `translator`, has the backend as `pyphenom` (`{version, path, found_by}` or `{error, searched}`), `executor: {kind: local}`, Python, platform, numpy and mcp versions. **Finding PyPhenom**: a plain import, then `PHNT_PYPHENOM` (the folder of `PyPhenom.pyd`), then the DLLs folder of the Python a venv was made from, then the usual Windows installs of this Python version. **A PyPhenom stand-in** (`tests/ppi_stub`, the tier-0 API with the probe's values) runs `PhenomAdapter`'s own code in the tests: it reads like the fake, `ppi.Phenom()` without arguments, the simulator as `Phenom('Simulator', '', '')`, every call it makes is tier 0. A test keeps `study_format` under 13 kB (11.9 kB). Author address as the template. README in the template's order (scope, install, use, a study, the checker with the assumptions about PyPhenom, how it works, for LLM tools). 65 tests. |
